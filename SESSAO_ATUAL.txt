## Sync Silent Payments automático + chunking 100 blocos/min (2026-09-22)
Problema real relatado: sync SP de 300-500 blocos morria no meio como se
estivesse offline (stream gRPC único muito longo em rede móvel).

Implementado e commitado:
- `SilentPaymentsSync`: faixa fatiada em janelas de `SCAN_CHUNK_BLOCKS`
  (100), com pausa de `SCAN_CHUNK_PAUSE_MS` (60s) entre janelas.
- Persistência incremental por janela: `onChunkCompleted` chama
  `WalletStorage.addSilentPaymentUtxos(chunkUtxos, chunkTipHeight)`. Se o
  stream morrer no chunk 4, os chunks 1-3 já estão salvos.
- `WalletViewModel`: `startAutoSilentPaymentsSync()` roda sync SP em
  segundo plano para carteiras Taproot/BIP86 com seed. Intervalo base 4min,
  backoff até 30min, timeout 10min. Mutex próprio (`spSyncMutex`) serializa
  sync automático e manual.
- Auto-sync agora roda em `Dispatchers.IO`, não na main thread.
- `WalletFragment`: status da Mochila mostra sync automático
  (em andamento/último horário/erro).
- Outros ajustes já pendentes desta linha de trabalho: DohFallbackDns,
  failover Electrum opcional, reconexão do stream gRPC, birthHeight
  best-effort sem pendência tardia.
- Fix do erro "Unable to resolve host oracle.setor.dev" depois de ~300
  blocos: `DohFallbackDns` agora é compartilhado por toda a vida do
  processo (o cache não é mais recriado a cada chunk) e tem fallback para
  Google + Cloudflare DNS-over-HTTPS.

Validação: `compileDebugKotlin` e `assembleDebug` OK. APK:
`Downloads/pkmbtcwallet-debug-20260922-180038.apk`.

## Saque Lightning → on-chain (2026-09-08, mesma sessão)
Felipe testou LN address + saldo total, funcionaram — mas perguntou "como
envio meus sats da LN pra onchain", não achou o caminho. Resposta: JÁ
EXISTIA na SDK sem eu ter percebido — `SendPaymentMethod.BitcoinAddress`
é só mais uma variante de destino aceita pelo MESMO `prepareSendPayment`
usado pra invoice/Spark address (a SDK reconhece um endereço Bitcoin
normal sozinha via `sdk.parse()`). O que faltava era só:
1. Passar `SendPaymentOptions.BitcoinAddress(OnchainConfirmationSpeed)` na
   hora de `confirmSend()` — só esse destino específico precisa disso (a
   velocidade de confirmação do saque, tem FAST/MEDIUM/SLOW). Hardcoded
   MEDIUM por enquanto, SEM seletor de velocidade na UI — pendência abaixo.
2. `previewOf()` calculava taxa 0 pra esse destino (caía no `else -> 0L`
   do `when` sobre `SendPaymentMethod`) — corrigido, soma
   `feeQuote.speedMedium.userFeeSat + .l1BroadcastFeeSat`.
3. UI: o campo "Enviar Lightning" não deixava óbvio que aceitava endereço
   Bitcoin normal — hint não tinha espaço, adicionei uma linha de texto
   explicando isso logo abaixo do campo (`dialog_lightning_send.xml`).
Ou seja: pra sacar, o Felipe só precisa colar o PRÓPRIO endereço on-chain
desta carteira (o mesmo do botão "Receber" normal, fora da Mochila) no
campo "Enviar" da seção Lightning — mesmo fluxo de "Verificar" → "Confirmar"
de qualquer outro envio Lightning, sem tela nova nenhuma.

## O que é este projeto
App Android de carteira Bitcoin em Kotlin, tema Pokémon (passphrase BIP39
usa nomes de Pokémon). BIP84 (Native SegWit) ou BIP86 (Taproot) por
carteira. Rede padrão MAINNET. Múltiplas carteiras, watch-only por xpub,
assinatura air-gapped via QR (PSBT real), controle de UTXO, node Electrum
próprio opcional (Floresta, ver projeto irmão), broadcast via Tor, e agora
Silent Payments completo.

## Feature Silent Payments (BIP-352) — RESUMO
Implementada do zero nesta sessão longa (várias madrugadas):
- Enviar pra endereço SP (Fase 1).
- Gerar/exibir próprio endereço SP (Fase 2).
- Escanear recebimento contra um oracle blindbit-oracle público (gRPC via
  Wire/Square) — `BlindBitOracleClient`, `SilentPaymentsScanner`,
  `SilentPaymentsConfirmer`, `SilentPaymentsSync` (network/); UI na
  Mochila (host do oracle por rede, status, botão "Sincronizar agora",
  checkbox opcional "Confirmar via Tor").
- Gastar UTXOs SP recebidos (só carteira BIP86/Taproot — BIP84 não gasta
  SP ainda, limitação documentada, exigiria assinador com witness
  heterogêneo por input).

Validado com PAGAMENTO REAL em MAINNET (o Felipe mandou fundos de verdade
antes do código estar validado ponta-a-ponta — 6 bugs reais encontrados e
corrigidos até fechar o ciclo, todos no git log entre `4bab012` e
`b76d99b`, resumo rápido):
1. Host do oracle vazando entre redes (chave de preferência compartilhada).
2. Trava de rede só aceitava "mainnet"/"bitcoin", oracle real diz "main".
3. Loop sem limite no scanner travava o app de vez (CPU puro, timeout de
   coroutine não interrompe loop sem ponto de suspensão).
4. MAIS IMPORTANTE: doc do blindbit-oracle mente sobre endianness — afirma
   little-endian, servidor real manda big-endian (formato de exibição).
   Confirmação de UTXO buscava txid que nunca existiu.
5-6. Saldo da tela principal e checagem "Saldo zero" no envio ignoravam
   UTXO SP já confirmada.
